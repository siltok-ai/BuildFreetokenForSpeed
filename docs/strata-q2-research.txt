加载与数值契约
完整 GGUF reader 校验 split、metadata、名称、形状、块类型、文件区间和映射覆盖；配置显式绑定来源回执，不能隐式回落 HF 主干。
Linear/Embedding/LM head 保留原始压缩块。每个融合段保留自身类型，不能按角色假设量化格式相同。不展开全部专家或整个 PLE。
PLE 使用第二片 IQ4_NL 的物理行宽90字节、逻辑宽160，与 RowStore 的稀疏读取、wait、预取及生命周期接合。
专家仍使用 FreeToken 的完整 host bank、GPU cache 与真实路由；计算为 Q2×Q8，权重64元素块 FP16 scale，激活32元素组 FP32 scale，FP32 SwiGLU、路由累积与输出。
压缩 dense 遵循 Strata native Q8_1 的 scale、舍入与原始输入 sum；BF16/F16/F32 存储的小矩阵输入保留 FP32。
FP32 residual、norm、router、GDN recurrent/conv 与 PLE 状态；主 QSA K/V FP16，index key、pending ring 与 index query FP32。资源预算应与实际 dtype 同步。
GGUF norm 保存 1+HF raw norm；FreeToken plus-one norm 加载时转换回 raw。ssm_a 已是 -exp(A)，直接使用，避免 log/exp 往返。
GDN value heads 已重排为循环顺序。Q/K head 映射使用 value_head % key_heads；V、z、a/b、conv V通道、decay、dt 和 out_proj 输入列须一致，不能套用 HF contiguous repeat。
所有改动由 GGUF 明确契约进入；原 HF/NVFP4/Q2opt2 路径仍需回归。

性能与核心优化
第一版必须先通过实际推理、数值与生命周期验证，再正式记录性能。完整压缩权重会降低主干显存与访存，不能预先推断 decode 一定提高或保证100tps。
根据 profile 优先：专家 cache 可用容量和策略、miss 的真实搬运量、搬运/计算重叠、CPU/GPU 协同及 MTP。避免在瓶颈未明确时反复微调单算子。
MTP 不是打开现有旗标即可使用：当前 FreeToken loader 不接入 MTP 权重与完整 propose/verify。需验证其权重来源、草拟/验证、接受率及额外资源。
MTP 必须覆盖 GDN recurrent/conv、QSA KV/index pending、PLE ngram/conv 的回滚、snapshot/COW、拒绝、取消和缓存复用。报告实际接受后的输出 token 吞吐，不能报告草拟次数当 decode。
若 MTP 或其他方向收益不足，以实际瓶颈和质量/资源代价作结论；不无限探索，不把 Strata 公布性能当本机结果。
