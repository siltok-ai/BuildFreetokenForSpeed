FreeToken Strata Q2 dev5：专家 decode 修复、实际性能与边界
2026-10-13；decode 优先，prefill 正确性、资源与性能回归仍需检查。

结果
当前实际安装候选为 0.1.3+speed.strataq2dev5，完整固定 GGUF、无 MTP、原生 FreeToken，尚未接入 Speed。
同一历史输入和 greedy 采样，短输入与 4K 各三次冷/热、每次实际输出 512 tokens：
4096 槽：短输入中位数 90.71 tps（89.74–92.02），4K 86.78（85.74–89.53）。
6144 槽：短输入中位数 104.05 tps（101.67–104.98），4K 99.35（94.22–100.41）。
6144 不是已准入的默认值：整机 peak commit 68,085,399,552 bytes，最低余量 2,272,460,800 bytes。
所有性能输出均达到 512-token 上限而非自然 EOS；decode 使用实际交付时间 (N-1)/(last-first)，排除加载和 TTFT。
相同输入在两个容量下的完整 token 序列均一致。4K 冷热均一致；短输入冷热在第 104/105 个 token（零基）开始分叉，不能宣称其逐位一致。
这已回到合理性能范围，尚未达成跨短/4K、资源合理、Speed 和随包完整验收的稳定 100 tps。

发现与修复
dev3 的主干投影错误地使用 BM16 矩阵路径处理单 token，宽输入/小输出的 HC down、inject 并行度很低。
dev4 用版本化 FreeToken AOT 模块承载经 MIT 授权移植的 Strata native MMVQ，保留压缩矩阵；BF16 权重/FP32 激活用 stride-aware 行 GEMV，合并同输入的 HC 投影。
主干 trace 从约 88.5 ms/token 降至约 4 ms/token；dev4 1024 槽约 51–54 tps、4096 约 62–64 tps。
dev4 专家仍将稀疏单 token 填充成 16-token tile，并让路由整理扫描整个缓存容量；4096 槽对齐约 1.18 ms/token，专家投影约 3.8 ms/token。
v12 首先只改路由计划，投影仍用 grouped，真实四次 512-token 为约 67–70 tps、冷热一致，说明扫描本身就是实质问题。
dev5 对非 prefill 且 T<=8 的专家路径改为按实际 routes 的 DP4A 向量投影。Q2 的原始 18-byte/64-element bank 和 slot 字节保持不变，Q8 激活 scale 保留 FP32，权重 scale 保留 FP16。
每 32 元素先做精确整数 dot 与 sum(x) 修正，再乘 scale、FP32 并行归约；gate/up、SiLU、down、路由权重合并均保持既有语义，不展开完整 BF16 权重。
decode 不再调用全缓存 histogram/align；prefill 和 T>8 保留 grouped 分支。
实际 dev5 4096 槽四份 32-token trace：专家投影 0.734–0.767 ms/token、对齐 0；主干 3.972–4.011；专家搬运 2.773–4.332；LRU 0.198–0.229。
GPU kernel sum 和 union 几乎相等，当前依赖链中可观察到的 GPU kernel 重叠很少。CPU 阻塞等待不得再加到 GPU 时间上。
短 trace 的冷 miss 状态与 512-token 稳态不同，不能用 32-token 的 profiler 吞吐代替长输出成绩。
6144 槽的短输入追加 trace 说明这一点：cold 搬运仍约 4.29 ms/token；hot 前 32 tokens 几乎全 hit，搬运约 0.08 ms/token，但真实 512-token 的 hot miss 中位数仍约 11.2%。不能把短热 trace 的全 hit 状态当稳定缓存收益。

正确性与限制
实际 wheel 的短/长上下文、真实 prefix hit、分支/恢复、取消后复用通过；4 组固定 token logits 比较通过。
长上下文比较 662 个组件，relative L2 最大为 0；12 个 QSA 选择相同。
20 题无 thinking 固定协议：dev5 15/20，原 FreeToken Q2 15/20，Strata 15/20，没有候选新增失败。
失败仍为 chain/fraction/binary_count 三个无 thinking 数字题，及两个答案数字正确但含 Markdown 围栏的严格 JSON 格式题。
新增专家 GPU 检查包含独立整数参考、T1/3/8/9 分支、稀疏高 slot（4095）、重复路由、空输入、CUDA graph 改输入与改路由；12 项通过。
实际安装的 GPU 合并测试是 18 passed / 1 failed，不能写成全部通过。唯一失败为历史逐位 prefill/decode 相等断言。
该 fixture 另行按已讨论的有限值/相对误差契约检查：相对 L2 约 1.14e-7–1.39e-7，最大绝对误差 5.59e-9，通过 3e-4 界限。
保留失败日志，不继续逐项追究同类 FP32 归约顺序差异；正式候选需在新的不可变修订中更新这一过时测试契约，不能覆盖 dev5 的 source/patch/wheel。
v13 原型首次严格 512-token 运行因短输入冷热 token 差异失败；v14 首次诊断受 chunk128 的历史探针 cold-label 假设限制，改用已建立的 chunk4096 诊断后通过。
以上失败全部保留，不能自动继承为新 wheel 的验收。

Strata 对照与下一重点
冻结 Strata 6674a0065fb96bacde33e3eb10f91a1df86f95f2 的 s2_expert_grouped.cu 也按 route/row 分组，用 DP4A 整数修正和 FP32 scale；CUDA/CPU 归约允许有界浮点差异。
它的 S2 blob 把 codes/scales 分开并交错 gate/up；FreeToken 原始 Q2 bank 布局不同，不能直接互相 reinterpret。
当前向量执行解决了与 Strata 设计的明显差距；继续围绕驻留、搬运、重叠和 graph 依赖做 trace，而非先调 LRU 的 0.2 ms 或少量算术指令。
Strata 同机无 MTP 历史 auto resident 13563 槽参考约 125.8 tps（短）/122.3 tps（4K），初始显存余量仅 221 MiB；不是缓存容量相同或已准入的部署配置。
其 resident RAM 为紧凑的专家补集，适应性换出时先 D2H 保存唯一副本并交换 ownership；FreeToken 当前仍保留完整 31.64 GiB host banks，再另配 GPU slot cache。
6144 槽下 FreeToken GPU 尚有约 9.47 GiB 可用，但 commit 余量约 2.1 GiB，说明仅按显存扩大缓存的策略不充分。
下一项设计见 strata-q2-expert-residency-design-20261013.txt。仍需实测 CPU Q2/PCIe 协同的收益，FreeToken 当前没有 Q2 CPU 专用执行器，不能宣称已有该优化。
本轮另用 Strata 自身 STRATA_DECODE_TIMING=1 / STRATA_VERIFY_PROFILE=1 采真实 native serve 阶段。GPU 行包括 waitA/B/CPU，并可能包括额外验证窗口，不能与 FreeToken 的 kernel sum 直接相加或逐项同名对应。
6144 槽诊断的 resident RAM 为 26.28 GiB：补集也会保留 prefill 借用区域所需副本，不能描述成所有 GPU 专家都完全删除 host 副本。该次整机 commit 有约 9.1 GiB 余量，但 physical_available 最低仅 381,018,112 bytes，同样不代表生产资源验收。
当前未装 nsys/ncu，当前进程也非管理员；不为工具准备中断性能工作，使用已可运行的 PyTorch CUDA trace 和 Strata native CUDA-event 计时。Nsight 环境准备另有条件记录。

prefill
主干暂统一使用逐 token MMVQ，使短/长执行契约清楚，但未利用大 batch 权重复用。4K cold TTFT 约 6.9 s，dev3 原先约 4.6 s，历史混合更快。
此回归保留，之后需实现正确的压缩 MMQ/批量 HC 计算；近期以 decode 的主要结构问题优先，不删除 prefill 验证或把回归说成已解决。
