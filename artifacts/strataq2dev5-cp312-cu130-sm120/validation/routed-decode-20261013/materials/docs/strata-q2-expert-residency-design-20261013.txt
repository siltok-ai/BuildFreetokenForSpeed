FreeToken Q2 专家驻留：基于当前 trace 的完整候选设计
2026-10-13；设计尚未实施或验收。主体始终是 FreeToken，Speed 后续只消费构建材料和资源配置。

问题与依据
dev5 4096 槽 decode 的主干约 4 ms、专家约 0.75 ms，而专家搬运约 2.8–4.3 ms。
增加到 6144 槽使 512-token 测量的 miss 从短约 21%/4K 25% 降到约 12%/14%，短吞吐到 104、4K 到 99 tps，但 commit 余量仅约 2.1 GiB。
FreeToken 的 cache_budget.py 当前主要按 GPU 做预算；host bank 保留全部专家，GPU cache 是另一个副本。Strata 的 FileExpertSource 则具备 compact complement 与 ownership exchange。
不能直接释放 GPU 命中专家对应的旧 host 行：现有 copy plan 和 prefill 都假设 layer-base + expert-id * row-stride，且完整 bank tensor 的引用会保留整块分配。

驻留与索引契约
新增可选、仅完整 Q2 模型使用的 protected-resident 策略，不改当前默认策略或其他量化模型的 bank schema。
每个 (layer, expert) 必须有一个永久、可恢复的权重 owner：GPU protected slot，或 compact pinned host 行。动态 LRU slot 只是 host owner 的可丢弃副本。
完整权重内容、FP16 weight scales、原始 Q2 bank 布局不变；不量化或替换权重。来源 tensor/专家行映射、文件完整 SHA 和 profile 来源固定并审计。
物理 cache 分为不相交区域：prefill 双缓冲、动态 LRU、受保护驻留。受保护区域不得被 LRU、prefill 借用、reset、重建统计操作覆盖。
GPU 路由索引必须保留专家到 slot 的映射；动态 miss 仅在动态区域装入，受保护命中不做 H2D。
对每个 bank 建稳定的 source pointer/index 表，支持同一层不同专家分别来自 GPU protected slot 或 CUDA 可读 pinned host 行；不能借用旧 per-layer 单 base 指针含义。
对下游 expert projection 仍呈现 GPU slot 和现有 bank 几何；新表属于缓存与搬运内部，Speed 不依赖其布局。
profile 初选受保护专家时可使用冻结、带来源/hash 的路由排名；排名只决定速度，不改变 route 或计算结果。无有效 profile 时安全回退现有完整 host + LRU 路径。

加载与资源预算
直接从完整 GGUF 流式加载到对应 owner，host 只分配 complement；不能先持有完整 host bank 再依赖删除少量 tensor view 来节省内存。
GPU protected slot 通过受监督的 stream 上传和同步建立，host compact banks 完成真实 Windows 注册与 device alias 验证，之后才创建指针表与捕获 graph。
每层 host complement 可有不同 expert 数量，须用显式 row-index，覆盖零行层和不等宽 bank，不以专家 id 当 compact 行号。
预算同时约束显存、pinned RAM、整机 commit、driver backing、KV、PLE、prefill 与 graph 暂存。实际测量 CUDA 分配对 commit 的增量，不将 cuda_mem_free 或 physical_available 当 commit 余量。
启动前算出所有区域与余量；不足时缩小目标容量/受保护数量或回退，不偷偷使用分页换出维持 benchmark。
保留多请求/取消/较长 prefill 的资源余量，6144 的当前 2.1 GiB 余量不可直接当生产默认。

prefill 与生命周期
prefill materialize 从 source pointer 表读取完整真实专家，protected owner 用 D2D，host owner 用 mapped/pinned 数据路径；目标只能是 prefill 区域。
next-layer staging 与当前读取区域的 ownership 保持不相交，用事件确保 buffer 复用时无读写竞态。若条件不满足，先使用同步但正确的回退，不产生 silent stale bank。
reset 只清动态副本/计数并恢复 protected 映射，不能丢 owner。prefix/cancel 不改变权重 owner；状态复用继续按原 engine 的 KV/GDN/conv/PLE 契约处理。
cache rebuild 必须在所有相关 stream 空闲且 graph 失效后重新分配/建立 source 表/恢复 protected 数据并 recapture；异常中止和 shutdown 释放所有注册映射，保持 hash 和可恢复来源。
初始实现使用固定 protected set，可测量和验证，不在单 token 路径做 ownership 交换。
若加入自适应 protected 交换，必须先为 victim 预留 host owner、D2H 完成后再复用 GPU slot，incoming H2D 完成后才能原子发布表；失败仍保留唯一正确副本。Strata 的 resident_stage_swaps/commit_exchange 是这一机制的对照。

内核与 graph
将 pointer-aware 多 bank gather 纳入 FreeToken 版本化 AOT/ABI，类型/宽度/设备/区域重叠检查明确；指针表地址稳定、内容 stream-ordered，graph replay 不依赖 host Python 临时地址。
沿用 dev5 routed DP4A，不为了新缓存重新展开权重。prefill grouped 或未来 MMQ 的输入映射不变。
纯 GPU 模式可先使用现有 miss 复制语义；CPU Q2 专用执行器属于另一个需 ROI 实测的可选方向，不假定已存在。
若增加 CPU/PCIe 分流，须给 Q2 格式建立真正的 CPU kernel、FP32 activation scale 一致性、route 顺序合并、CPU/GPU doorbell 与取消协议，并比较等待能否被隐藏；不能只从 Strata 搬一个计算函数而缺少生命周期。

验证与构建
独立参考校验 compact-row/高 slot/重复 route/全 hit/全 miss、零 host 层、owner 与动态副本一致性、prefill 双缓冲覆盖和 rebuild；CUDA graph replay 改 route、pointer 内容/ownership 后验证读到正确行。
真实短/4K/稀疏长上下文、prefix 分支/恢复、取消后复用、EOS/thinking、资源压力和必要多请求均保留；允许有界 FP32 归约差异，不能忽略行错位、非有限数值、陈旧状态或新增质量失败。
对照当前 dev5 同输入同采样，记录实际长输出、miss、payload、CPU/PCIe 分流、GPU kernel/等待与整机 commit。固定 token 或同输出情况下区分缓存收益与路由变化；不要把 CPU 等待加在 GPU 时间上。
profile/patch/version/源码 replay/AOT spec/制品 SHA/依赖与许可链必须形成新的独立修订，不修改被冻结的 dev4/dev5 制品；过时 bitwise 测试契约也在新修订中明确更新。
既有量化格式和已验收旧模型执行不受新策略影响，仍需实际回归。正确性与资源完成前不自动让 Speed 默认采用新配置。
